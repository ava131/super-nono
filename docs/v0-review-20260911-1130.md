### 决定 1 — 气泡采用「方案 B：独立新窗口」【已决】

**PM 原话**：

> 气泡那个，我觉得应该是点击之后再旁边新开一个窗口。

**对应编号**：这是方案 **B**（独立新窗口），不是方案 A（单窗口扩窗）。

**为什么最终推 B（尽管上一轮开发曾推 A）**：

- 上一轮推 A 的唯一理由是内存：`PRD-Body` §6.1 第 212 行假设「Renderer 与窗口数量成正比 80–150MB」。两个渲染进程会让 A9 的 ≤300MB 直接顶破。
- **但 B 的理由比内存更硬**：B 让命中测试保持纯净。方案 A 中窗口一大，`setIgnoreMouseEvents` 是全窗口生效的，气泡区域也得靠「alpha ∪ 气泡矩形」两套逻辑来判定穿透——这是最容易出玄学 bug 的地方（拖不动、点不到、边缘闪烁）。方案 B 中宠物窗永远是 160×160，命中测试就是纯粹的 alpha 判定，一行都不用改；气泡窗是正常窗口，正常收所有事件。
- 代价：A9 从 ≤300MB 放宽到 **500MB（PM 已于 11:45 拍板，见 §2 决定 7）**（PM 为 16GB M2，为一个 160×160 宠物多花 100MB 被认为划算）。
- **纪律要求**：这条代价必须在 PRD 里认账，不能装作没发生。否则 M4 一测就「不达标」，然后回头吵架。

**B 方案实施要点（4 条，必须写进 SDD）**：

1. **气泡窗 `focusable: true`，宠物窗 `focusable: false`。** 键盘输入必须落在气泡窗上。
   - ⚠️ **这是 B 方案最大的风险点，也是 M2 第一个必须验证的东西**：应用是 accessory 模式（`app.dock.hide()`），气泡窗能不能成为 key window 拿到键盘焦点？**拿不到就打不了字。推演不管用，必须实测。**
2. **气泡窗只创建一次，打开 = `show()`，关闭 = `hide()`，绝不 destroy**——沿用 `PRD-Body` §6.3 第 1 条的纪律。
3. **定位由主进程计算，渲染进程不掺和。**
   - `x = petCenterX - bubbleW / 2`
   - `y = pet.y - bubbleH - 8`
   - 贴边则 `clamp` 到 `workArea`
   - 上方空间不够则翻转到宠物下方
   - 宠物拖动时：**建议直接隐藏气泡**（松手不自动弹回）。这比「跟随移动」实现简单，且避免高频 `setBounds`。
4. **穿透逻辑完全不用动。** 气泡窗没有透明区域需求，它就是一块正常的活动面板。Esc / 点别处关闭由气泡窗自己监听，不需要跨窗口协作。

**意外收益**：既然气泡是独立窗口，`PRD-Body` W-1 第 79 行「窗口尺寸 = 精灵尺寸 + 四周留白」这条措辞**保留原样即可**，不必改成「两个尺寸状态」。文档改动量比方案 A 更小。

**待重算**：`PRD-Body` §6.1 的内存表与 A9（第 279 行）、SDD §3.2 进程模型表（第 101–105 行）需按双渲染进程重算，**上限取 500MB**（见 §2 决定 7）。

### 决定 2 — 提示词时间注入位置：移到本轮 user 消息，**不**走天气 skill【已决】

**PM 原提议**：

> 我们不是有一个天气 skill？调用之前先请求一次当前时间就好了。

**评审结论：不采纳 PM 这个提议，改采纳「时间移出 system message」的方案。PM 已同意。**

**为什么不能用天气 skill 替代**（三条理由）：

1. **它只解决「天气」这一个场景。** B-3 要当前时间是为了「今天几号」「还有几天到周末」「三小时后提醒我」——这些跟天气无关。天气 skill 返回的观测时间**不能**当系统时间用。
2. **多一次工具调用 = 多一次模型往返 = 更慢更贵。** 时间是已知信息，让模型调工具去拿是纯粹的成本。
3. **时间语义不同。** 天气 skill 自带的观测时间戳（`PRD-Skill` §6.3 第 7 步、§6.4 WX-3）表达的是「数据是哪一刻观测的」，与「现在是几点」是两件事，不该合并。

**采纳的方案**：时间不进 system message，而是拼在**本轮 user 消息前面**，例如：

```
[现在是 2026-09-11 14:20 周四] <用户原话>
```

system message 中只剩人格 + 技能清单 + 安全规则，**一个字都不随请求变化**。

**收益**：

- B-3 的「时间感知」照样满足，AB4（问「今天几号」）照样过；
- B-6e 的「稳定前缀」真正成立，DeepSeek 的前缀缓存能命中；
- 不新增任何工具调用。

**改动量**：`PRD-Brain` B-3 第 140 行删掉「当前时间」；§5 时序图第 452 行加一句；SDD 第 207 行 `persona.js` 的职责从「注入当前时间」改为「提供稳定前缀」。约半小时工作量，省的是每次请求的真金白银。

### 3.3 B-4：IPC 契约（W-9，已标「冻结」）漏了 4 类频道【待执行 —— 核心阻塞项】

> **【记录】给 PM 的比喻**：W-9 那张表，等于给了我一栋楼的房间清单，**但没给楼梯**。房间都在，走不过去。以下「楼梯」缺失。

**① 设置面板没法读写设置。**
- `PRD-Body` W-7 第 132–136 行有 5 个设置项（API Key / 模型 / 缩放 / 自启 / 清理数据）。
- `SDD` 第 196 行说设置面板放在气泡里（渲染进程），但实际存配置的 `settings.js` 在主进程。
- **渲染进程要把 Key 交给主进程，得有频道。表里一个都没有。**
- → 缺 `settings:get` / `settings:set` / `settings:clearData`。

**② 点击穿透的开关没有频道。**
- `SDD` §6.2 示例代码第 269–270 行直接写了 `api.setIgnoreMouse(false)`。
- **这个 `api.setIgnoreMouse` 在 W-9 表里不存在。** 即示例代码用了契约里没有的东西，文档自相矛盾。
- → 缺 `pet:setIgnoreMouse`。

**③ 调试面板拿不到主进程的内存。**
- `PRD-Body` W-8 第 140 行 / `SDD` 第 197 行要求显示「主/渲染进程内存」。
- 渲染进程只能读自己的内存，**读不到主进程的**（`process.getProcessMemoryInfo()` 只给当前进程）。
- → 缺 `debug:metrics`（主进程定时推给渲染进程）。

**④ 上一轮的回答可能串台（测试最担心的一类 bug）。**
- 用户点「停止」，马上又发一条新消息。此时旧请求的 `brain:delta`（逐字流）可能还在路上飞。
- `W-9` 表里 `brain:delta` 的载荷只有 `{ text }`，**没有任何标识说明「这段字属于哪一轮」**。
- 结果：上一轮的字飘进新气泡里。偶发、难复现。
- → 所有 `brain:*` 事件统一带 `turnId`，渲染进程丢弃不属于当前轮的 delta。

**⑤ 附带发现 — `pet:stateChanged` 语义可疑。**
- W-9 表里写「上报状态（供调试面板）」，但状态本来由主进程通过 `brain:state` 下发。
- 宠物本地进入 `drag` 状态时主进程并不知道——所以该频道的真实用途是「渲染进程本地状态上报」。
- 需在文档中写明它与 `brain:state` 的**优先级 / 合并规则**，否则调试面板显示的状态会来回跳。

**已决的流程性结论**：
> **把 W-9 的「冻结」降级为「v0 草案，M2 开始时冻结」**，M0/M1 期间允许增补频道。M2 冻结时至少补齐：`pet:setIgnoreMouse`、`pet:click`、`settings:get/set/clearData`、`debug:metrics`，并为所有 `brain:*` 事件加 `turnId`。
>
> **理由**：冻结一个跑不起来的契约，比不冻结更贵。

### 3.4 点击 vs 拖动 没有判定规则【已决，见 §2 决定 3】

## 6. 更好的选择（有取舍，供 PM 拍板）

1. **`brain:delta` 只发增量，但 UI 层做「合帧渲染」。** 现在每个 delta 直接触发 DOM 更新，流式快时每帧多次 reflow。建议 delta 进队列，按 16–60ms 批量 flush。改动不大，能同时改善长回答时的 CPU 与观感。【建议】
2. **把「每天 token 上限」改成「每天费用上限」。** 用户对钱敏感、对 token 没概念；有了 B-6a 的 `cost_est`，加个价格表（`config/pricing.json`，可手动更新）就能按钱卡。
   - **附带**：文档没有 DeepSeek 价格表来源，`cost_est` 会随官方调价失真，需写清「估算仅供自用参考，不保证与账单一致」。【建议】
3. **L2 确认的「本次会话内记住」建议 v0 别做。** 它是个安全相关的记忆，v1 的 email 技能才用得上；现在做等于增加一条没人测的攻击面。文档已写「发送类永不记住」，那 v0 干脆全不记住。【建议】
4. **调试面板的内存显示改成「主进程定时推送 + 环形历史（最近 5 分钟曲线）**，而不是只显示瞬时值。慢速泄漏（24h 跑测的核心关切）看瞬时值看不出来，看曲线一眼就知道。【建议】
5. **把 `test/` 的 3 个文件扩成明确的分层清单并写进 SDD §9，同时补 `pnpm soak`**（mock provider 长跑）。这是 A10 / AB13 能否真被执行的前提。【建议】
6. **M3/M4 之间加一条「mock provider」交付物。** 它同时解锁 AB7、AB12、人格回归、soak 测试——性价比最高的内部工具，文档里目前完全没有。【建议】
