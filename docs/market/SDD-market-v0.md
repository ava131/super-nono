## 2. 技术选型

### 2.1 结论

> **数据源主备顺序由「使用地点」决定**（评审决定 1/2）。PM 长期在**国内**使用，故：

| 层次 | 选型 | 理由 |
|---|---|---|
| **数据源（主）** | **东方财富 `push2his`** | PM 在国内使用；东财是境内源，**国内快且稳定**；**`fqt=1` 直接返回前复权 OHLC**，不需要自己算因子 |
| **数据源（备）** | **Yahoo Finance chart API** | 当前海外开发环境**实测完全可用**（86ms，`adjclose` 齐全）；国内大概率不可达，故只作**降级路径** |
| 符号解析 | **本地表优先 → 东财搜索 → Yahoo search 兜底** | 用户最常问自选股里的票，本地命中就不出网。⚠️ **Yahoo 搜索不支持中文名**（实测），中文名解析必须靠本地表 + 东财搜索 |
| 指标计算 | **手写纯函数** | 已落地：`skills/market/indicators.js`。引库会破坏「除 Electron 外零运行时依赖」，而这段代码最该被单测锁死 |
| 存储 | `node:sqlite`（已有，**Node 内置**） | 新增 `skill_kv` 表。⚠️ 不是 `better-sqlite3`（无原生模块、无 ABI 重建） |
| 图表 | **v0 不做** | 见 PRD §9.1 |

#### ⚠️ 必须诚实标注的两个不确定性

1. **东财在国内的可用性【待验证】**：2026-09-14 在**海外**环境实测东财 K 线端点**不通**
   （`HTTP 000`；DNS 通、TCP 通、**TLS 握手成功**、服务器主动 `Empty reply` —— 典型的**端点级应用层封锁**，
   符合"境内源拒绝海外 IP"的特征）。**因此在 PM 的国内环境应可用，但无人实测过。**
   → **M-0 第一步：在国内跑一次 curl 验证**（命令见 `IMPLEMENTATION-STATUS.md` §2）。
2. **Yahoo 在国内大概率不可达【推断】**：属公开常识，但未针对 `query1.finance.yahoo.com` 在境内实测。

**由此得出的一条必须写进产品的结论**：

> **在国内的正常使用场景下，东财实质上是唯一源。**
> 备源 Yahoo 只在海外网络下起作用。**所以"东财挂掉"在国内等于"今天查不到行情"**
> —— 这不是设计缺陷，是必须如实告知用户的能力边界，**不许装作有备份**。

#### 端点级封锁的实测细节（供 v1 复用）

| 端点 | 海外实测 | 说明 |
|---|---|---|
| 东财 `push2his`（历史 K 线） | ❌ 不通 | **我们要用的就是它** |
| 东财 `push2`（实时报价） | ❌ 502 | v0 不需要（`quote` 从 K 线最后一根派生）|
| 东财 `search-api-web`（搜索） | ✅ **HTTP 200** | **符号解析仍可依赖它**（即使 K 线不通） |
| Yahoo chart | ✅ 200 / 86ms | 备源路径 |

### 2.2 被否决的方案

| 否决项 | 理由 |
|---|---|
| **AKShare / Tushare** | 都是 Python。引入意味着多一个运行时、多一套打包与进程守护——这个取舍在天气技能那轮已经做过一次（否决 Python），理由不变 |
| **Alpha Vantage / Finnhub / Twelve Data** | 需要 API Key，免费额度太小（Alpha Vantage 25 次/天，扫一次自选就用光了）。而且**多一个密钥就多一个泄露面** |
| **老虎证券 OpenAPI** | 需**老虎账户**并在后台申请 API 权限（`tiger_id` + 私钥 + token），行情还可能有授权档位。**v0 不做美股，不涉及**；将来做美股时再与"东财美股通道（零 Key）"比较 |
| **Stooq** | 免费 CSV，但只到日线且 A 股覆盖一般，作为备源不如东财 |
| **`technicalindicators` npm 包** | 纯 JS 可用，但为 ~400 行代码引一个依赖不划算；更关键的是**它的 EMA 种子 / MACD 柱口径未必和 A 股行情软件一致**，而一致性是本功能的验收项（MK4 / MK5）。**已自研并单测通过** |
| **Yahoo 官方 `yahoo-finance2` 包** | 本质是同一个非官方接口的封装，但会随上游变更而滞后；我们只需要 chart 一个端点，直接用 safeFetch 更可控（而且必须走 safeFetch 才过白名单） |
| **Excel / CSV 手工维护自选** | 用户要的是"问一句就知道"，手工维护就失去意义了 |

> **修正说明**：原稿把 Yahoo 列为**主源**、东财列为**备源**，理由是"Yahoo 一套代码全覆盖"。
> 该判断**未经实测**，且与 PM 的实际使用地点（国内）相反。实测结果是：
> **Yahoo 拉 A 股完全可用（海外 86ms、`adjclose` 齐全）**，但**国内大概率不可达**；
> **东财 K 线在海外被端点级封锁**，国内应可用。故主备互换。

### 2.3 关键取舍（一句话）

> **用"境内单主源 + 海外备源"换"零密钥、零 Python、零新依赖"；用"只做日线"换"彻底规避限流"。**
>
> ⚠️ 代价是**国内没有真正的第二源** —— 这一点必须在产品层面诚实告知（见 §2.1）。

## 3. 新增的架构能力

本功能需要给技能系统补**两项通用能力**（天气用不上，但邮箱 / 提醒等后续技能都会受益）。

### 3.1 `ctx.store` —— 技能持久化契约

**问题**：现有技能是无状态的（只有内存缓存）。自选股是**用户数据**，必须持久化。

**方案**：给技能注入一个命名空间隔离的 KV 存储。

```js
// src/main/skills/store.js（新增）
/**
 * @param {string} namespace 技能名，自动隔离
 */
export function createSkillStore(namespace) {
  return {
    get(key),            // → unknown | null
    set(key, value),     // 值会被 JSON 序列化
    delete(key),         // → boolean
    list(prefix),        // → { key, value }[]
    clear(),             // 清空本命名空间
  };
}
```

底层是 SQLite 的一张通用表（见 §6.1）。在 `runner.js` 里与 `safeFetch` 一起注入：

```js
const fullCtx = {
  ...ctx,
  safeFetch: egress.safeFetch,
  store: createSkillStore(name),   // ← 新增
  skillName: name,
};
```

**边界（重要）**：

- 技能**只能看到自己的命名空间**，读不到别的技能的数据。
- **不能**用它存密钥（那走钥匙串）。
- **双上限**（评审决定 9）：**单 key 64KB + 单命名空间 1MB**，防止技能把数据库当垃圾场。
  （原稿只有"单值 64KB"；但 `watchlist` 是整存一个数组，将来加"备注"字段可能撑到，故补总上限。）
- 这部分数据**不进上下文**，模型只能通过技能主动读出来。

#### ⚠️ 必须加运行时写闸门（评审决定 9 / B-4）

`createSkillStore` **不能只做命名空间隔离，还必须做权限隔离**：

```js
// src/main/skills/store.js（新增）
/**
 * @param {string} namespace 技能名，自动隔离
 * @param {{ risk: string }} decl  技能声明 —— 用来决定是否允许写
 */
export function createSkillStore(namespace, decl) {
  const writable = decl.risk !== 'read_only';   // ★ 只读技能不得写
  const guard = () => {
    if (!writable) {
      throw new AppError('PERMISSION_DENIED',
        `技能 ${namespace} 声明为 read_only，不允许写入 ctx.store`);
    }
  };
  return {
    get(key)         { return readRaw(namespace, checkKey(key)); },
    set(key, value)  { guard(); ... },   // ← 写操作必须过 guard
    delete(key)      { guard(); ... },
    list(prefix)     { return listRaw(namespace, checkKey(prefix)); },
    clear()          { guard(); ... },
  };
}
```

**为什么必须有这个闸门**：命名空间隔离**只防"读到别人的数据"**，不防"只读技能往里写"。
一个声明 `read_only` 的技能若能 `set()`，就能污染**别的技能会当作可信来源读取**的数据。
`PRD-market` §12 写的"判定条件写死"解决的是**声明**问题，解决不了**越权调用**问题。

**key 白名单**：`checkKey` 用 `^[a-z0-9_:.-]{1,64}$` 校验，防越界与超长 key。

**⚠️ 现状**：`ctx.store` **目前尚不存在** —— `runner.js` 只注入 `safeFetch` 与 `skillName`，
`src/main/skills/` 下没有 `store.js`。所以这是**实现时不可遗漏的要求**，不是已存在的保护。

### 3.2 `local_reversible` —— 新增风险等级 L1.5

**问题**：`risk` 是 per-skill 的。"加自选"是写操作，但让它逐次弹确认框会**训练用户盲点"允许"**，反而降低安全性（PRD §5.1）。

**已采纳**（评审决定 3，PM 确认）：在现有三级之间插入一档。

| 等级 | risk 取值 | 判定 | 行为 |
|---|---|---|---|
| L1 | `read_only` | 只读、纯本地 | 直接执行 |
| **L1.5** | **`local_reversible`** | **只写本技能 `ctx.store` + 存在反向操作 + 不外发写入** | **直接执行（不弹框）**；**结果必须在气泡里可见** |
| L2 | `local_write` / `external_send` | 外发数据、读隐私内容、不可撤销的本地写 | 弹确认框，**超时即拒绝** |
| L3 | `irreversible` | 涉及金钱或不可逆后果 | 硬拒绝 |

**判定必须写死**（防止将来有技能把危险操作伪装成 L1.5）：

> 同时满足三条才算 L1.5：
> ① 写入范围**仅限本技能的 `ctx.store`**；
> ② 存在**一条反向操作**能完整撤销（如 `add` ↔ `remove`）；
> ③ **不产生任何外发写入**（不通过网络发送用户数据）。
> ⚠️ **出网只读查询不受此限** —— 原稿写"不产生任何出网请求"，**比 L1（只读）还严，自相矛盾**
> （纯只读技能当然可以出网，如 `weather`）。已按评审决定 10 修正。
>
> **任一条不满足即降为 L2。**

#### 「不弹框」之后的安全网

因为不弹确认框，用户失去"事前拦截"，只剩"事后纠正"。因此：

| 项 | 处置 |
|---|---|
| **结果在气泡可见** | ✅ **必做** —— "已加入自选：贵州茅台" |
| **自选名单每行可删** | ✅ **必做**（见 PRD §8）—— 这就是事后纠正的落点 |
| **"撤销上一步"按钮** | ⚠️ **可选优化，不是 L1.5 的前提** —— 条件②已由 `remove` 满足 |
| 若做撤销 | 用**快照 + 整体回滚**（`skill_kv` 里存最近 5 次），天然规避索引漂移 |
| **"说话触发撤销"** | ❌ **不做** —— 界面的归界面，让模型判断"撤销哪一步"容易出错 |

**对现有代码的影响**：

| 文件 | 改动 |
|---|---|
| `src/main/skills/schema.js` | `RISK_TO_LEVEL` 新增 `local_reversible: 'L1.5'`；校验规则从"非只读必须确认"改为"**L2/L3 必须确认**；**L1.5 不得要求确认**" |
| `PRD-Skill-v0.md` §4.2 | 表格新增一行 |
| `PRD-Skill-v0.md` §3.2 | `requiresConfirmation` 校验规则同步（见上） |

## 5. 关键实现

### 5.1 复权因子换算（最容易错的一环）

**背景**：Yahoo 返回的是**原始 OHLC** + **复权后的收盘价 `adjclose`**。
但均线和 MACD 需要**复权后的整根 K 线**，只调收盘价会让形态失真。

**算法**（逐根 bar）：

```
factor_i  = adjclose_i / close_i          // close_i 为 0 时跳过（停牌）
adj_O_i   = open_i  × factor_i
adj_H_i   = high_i  × factor_i
adj_L_i   = low_i   × factor_i
adj_C_i   = close_i × factor_i            // == adjclose_i
```

**结果性质**：最新一根的 `factor ≈ 1`，历史被等比缩小 → 这是**前复权**
（最新价不变、历史价调整），正是技术分析要的口径。

**必须处理的边界**：

| 边界 | 处理 |
|---|---|
| `close_i` 为 0 或 null（停牌） | 跳过该根；若连续缺失超过阈值，**报错而不是猜** |
| `adjclose` 数组缺失或长度不一致 | **降级为不复权，并在输出里明确标注**（不许静默当复权用） |
| `adjclose_i == close_i` 全部成立 | 说明该标的从未分红送转，正常 |
| 除权当天 | 复权后价格应**连续无跳空** —— 这正是 MK3 的验收方式 |

**备源东财不做这个换算**：它 `fqt=1` 返回的已经是前复权 OHLC，直接用。
但两个源的前复权基准可能略有差异，所以**输出必须标注数据源**。

> ⚠️ **本节只服务 Yahoo 路径**（备源）。东财（主源）路径**跳过本节**。
> 评审曾建议"本节可删"——那是基于"东财单源"方案；在现方案（东财主 + Yahoo 备）下
> **本节必须保留**，它是备源路径的必要步骤，是双源的**代价**不是收益。

### 5.2 符号解析

**目标**：用户能说"茅台"，也能说 `600519`。（v0 只做 A 股。）

**统一内部格式**：`<code>.<MARKET>`，如 `600519.SH` / `000001.SZ`。

**解析顺序**（越靠前越省事）：

1. **自选股本地表**（`ctx.store`）—— 用户最常问的就是自己加过的票，精确 / 前缀匹配
2. **内置常用表**（`known-symbols.json`）—— 覆盖两市主要标的，零出网
3. **网络搜索** → **东财搜索优先，Yahoo search 兜底**
4. 都不中 → **返回候选列表，不猜**（复用天气技能 WX-4 的原则）

**各源符号转换**（v0 只需前两行）：

| 内部 | Yahoo | 东财 `secid` |
|---|---|---|
| `600519.SH` | `600519.SS` | `1.600519` |
| `000001.SZ` | `000001.SZ` | `0.000001` |
| ~~`00700.HK`~~ | ~~`0700.HK`~~ | ~~`116.00700`~~（v1+） |
| ~~`AAPL.US`~~ | ~~`AAPL`~~ | ~~`105.AAPL`~~（v1+，美股前缀见下） |

> ℹ️ **v1+ 做美股时的坑（登记）**：东财美股 `secid` 前缀**不是固定的 105**：
> **105 = NASDAQ / 106 = NYSE / 107 = AMEX**，而且**这个前缀本身要先请求 suggest 端点解析出来**。
> 因此"查一支美股"会比 A 股**多一次出网**。

> ✅ **中文名解析已有实测结论**（原稿标"待实测"，现已有答案）：
> **Yahoo search 对中文股票名完全不可用**（「茅台」「宁德时代」「长江电力」**均无结果**）；
> **东财搜索完美**（「茅台」→ 600519.1；「宁德时代」→ 300750.0）。
> 因此中文名解析**必须依赖本地表 + 东财搜索**，Yahoo 只在英文/代码直通时有意义。
> 内置表规模目标：**沪深 300 + 主要指数 ≈ 320 条**。

### 5.3 指标计算（公式与口径）

**✅ 已实现**：`skills/market/indicators.js`（纯函数，零依赖）+ `test/unit/indicators.test.js`（35 用例）。
**参数集中在 `PARAMS` 并 `Object.freeze`** —— 改参数等于改验收口径，必须同步改文档。

| 指标 | 实现要点 |
|---|---|
| **SMA(n)** | 简单平均；不足 n 根时返回 `null`（**不许用短样本充数**） |
| **EMA(n)** | 平滑系数 `α = 2/(n+1)`；**种子用前 n 根的 SMA**（与 TA-Lib / 行情软件一致，用首值做种子会整体偏移） |
| **RSI(14)** | **Wilder 平滑**：种子 = 前 14 期涨跌幅的简单平均；之后 `avg = (prev×13 + cur)/14`；`RSI = 100 − 100/(1+RS)`；`avgLoss == 0` → RSI = 100（全平则 50） |
| **MACD(12,26,9)** | `DIF = EMA12 − EMA26`；`DEA = EMA9(DIF)`；**柱 = 2 × (DIF − DEA)** ← A 股软件惯例，**必须乘 2** |
| **量比** | 当日量 ÷ **前 20 日**均量（**不含当日**，评审 B-4 统一口径） |
| **区间位置** | `(P − min250) / (max250 − min250)` |
| **分位** | `count(close ≤ P) / N`（N = 实际样本数）。⚠️ 输出必须带中文读法，见 PRD §4 |
| **波动率** | 日收益率标准差 × √252（年化） |
| **均线关系** | 价格与各均线上下关系；并回溯"最近一次穿越发生在几根 bar 之前" |

> **⚠️ 单位口径（评审 C-3）**：`SUMMARY_LIMIT` 按 **`String.length`（UTF-16 码元）** 判定，**不是字节**。


**样本不足的处理**（MK16）—— **两档，别混为一谈**：

| 档 | 判据 | 行为 |
|---|---|---|
| **算不出来** | `N < MIN_SAMPLES[指标]` | **不输出**（`null`），并在 `insufficient` 里说明 |
| **算得出来但偏短** | `MIN_SAMPLES ≤ N < RELIABLE_SAMPLES` | **照常输出**，但在 `unreliable` 里标注"相对不可靠" |

具体数值见 `indicators.js` 的 `MIN_SAMPLES` / `RELIABLE_SAMPLES`：

- `N < 250` → 分位 / 区间位置**不输出**
- `N < 34` → MACD **不输出**；`34 ≤ N < 60` → MACD **输出但标注"相对不可靠"**
- `N < 15` → RSI **不输出**；`15 ≤ N < 60` → RSI **输出但标注**
- 量比 / 波动率同理（下限 21，建议 60）

> ⚠️ **修订说明**：原稿只写了"`N < 60` → MACD 标注不可靠"，但没写下限，
> 于是代码按数学下限 34 就**静默**给出 MACD —— 文档与实现不一致，
> 且**静默的那一侧更危险**（用户以为它和 60 根时一样可信）。
> 现在两档都在文档里写明。

### 5.4 缓存与限流

| 机制 | 设计 |
|---|---|
| **缓存命中条件** | **① 距上次拉取 < 6 小时，且 ② 缓存里最后一根 K 线的日期 == 该标的最近一个已收盘交易日。两条同时成立才算命中。** |
| 缓存层 | 内存 Map（快）+ `ctx.store`（跨重启）|
| 键 | `kline:{source}:{symbol}:{range}` |
| **缓存存什么** | ⚠️ **必须明确**：**存原始数据**（元数据 + 原始 OHLC），**不存算好的复权价**。理由：前复权以**最新一根为基准**，每过一天全序列历史价都会微调；若存复权后结果，用户会拿两次对话的数字对照并发现不一致（评审 B-3） |
| ~~报价缓存~~ | ❌ **删除** —— v0 只做日线，**不存在"报价"**。`quote` 从日线最后一根派生，零额外请求 |
| 请求节流 | **串行**，相邻请求间隔 **≥ 500ms**（评审 A-2：东财按源 IP 限流，200ms 偏激进） |
| 单次上限 | 一次 `scan` 不超过 20 只 |
| 失败隔离 | 单只失败只标注该只，**不影响其余** |
| 超时 | `scan` 的 `timeoutMs` 设为 **45000**（评审 B-9：实测 20 只 7–19s，P95 下 30s 余量不足） |
| **中断检查** | ⚠️ `scan` **每次循环前**检查 `signal.aborted`，中断即抛 **`CANCELLED`**，**必须与 `TIMEOUT` 区分**（否则用户点「停止」会看到"超时"文案，评审 B-8） |

> **首次冷启动会慢**（实测 7–19 秒），之后当天命中缓存就很快。
> 这一点必须让用户能感知到——`scan` 开始时给一句提示（走 `brain:notice`），
> 并且**不能**在 15s 默认超时下被误杀（所以 `skill.json` 必须声明 `timeoutMs: 45000`）。

**"最近已收盘交易日"的计算（评审 D-1 / D-2 修订）**：

- v0 **不判断节假日** —— 靠"**最后一根 K 线日期 + 6 小时 TTL**"两个条件同时成立即命中，天然规避长假反复拉取。
- **盘后宽限期**：A 股 15:00 收市，但当日 K 线通常 **15:30–16:00** 才稳定。
  因此**收盘后 60 分钟内不认为"当日数据可用"**，此时按上一交易日数据回答，
  并在输出里标注（如 15:10 提问 → "数据截至 2026-09-11 收盘"）。
- **时区**：v0 只做 A 股，统一按 UTC+8，**不需要三市场时区换算**。

> ⚠️ **限流是双向的，且开发期极易撞上**（实测教训）：
> 跑探针时约 **160 次请求/10 分钟** 即把**东财打硬封**（TLS 通、HTTP 层 `Empty reply`），
> **Yahoo 也在 ~40 次/2 分钟触发 429**。
> 因此四条纪律：① **缓存是保护不是优化**；② **绝不激进重试**，被拒后要退避；
> ③ **被封时的措辞要诚实**（"数据源暂时拒绝了请求，过会儿再试"，**不是**"查不到这只股票"）；
> ④ **开发调试一律用 fixture**，不打真实接口。

### 5.5 批量扫描的 summary 预算（必须提前设计）

`SUMMARY_LIMIT = 800`（`runner.js`），但 20 只股票的完整指标远超。

> **单位（评审 C-3）**：按 **`String.length`（UTF-16 码元）** 判定，**不是字节数**。
> 中文 UTF-8 一字 3 字节，按字节算会超标 3 倍。**实现与测试都按 `String.length` 核对。**

**方案：`scan` 使用紧凑表格，每只一行。**

```
贵州茅台 1680.0 +1.2% RSI28 位87% 量1.8
宁德时代  220.5 -0.8% RSI55 位42% 量0.9
...
```

- 20 行 × 约 38 单位 ≈ **760 单位**，刚好在预算内。
- **超限时的降级顺序 —— 减行，不减列（评审 D-4）**：
  1. **列必须固定**。原稿"先去掉量比列 → 再去掉区间位置列"会让**列数变化**，
     模型可能把第 5 列当成第 4 列读错。
  2. 改为：**按"涨跌幅绝对值从大到小"保留前 N 只**（信息量最大的优先），
     末尾加一行 `（另有 M 只未显示，用 overview 单查）`。
  3. 仍超限 → 继续减少行数，直到满足预算。
- **绝不**把某一行截成半句，也**绝不默默丢列**。

### 5.6 数据源降级

```
market.overview(symbol)
  ├─ 符号解析（本地表 → 东财搜索 → Yahoo search 兜底）
  ├─ 缓存命中？ → 用缓存（6h TTL + 最后一根 K 线日期）
  └─ 未命中
       ├─ 主源 东财 ──成功→ 已是前复权 → 指标 → snapshot（标注来源）
       │              └失败┐
       └─ 备源 Yahoo ←────┘ ──成功→ adjust 复权换算 → 指标 → snapshot（标注来源）
                              └失败→ 如实报错

  中断：每次循环前检查 signal.aborted → 抛 CANCELLED（与 TIMEOUT 区分）
```

**⚠️ 失败措辞必须分两种情况**（评审 A-3 第 3 条）：

| 情况 | 说法 |
|---|---|
| 域名/接口被拒（429、Empty reply、网络不通） | 「**数据源暂时拒绝了请求，过会儿再试**」 |
| 该标的确实不存在 | 「**查不到这只股票**」 |

**这两种必须区分** —— 混在一起会误导用户（"查不到"暗示股票代码错了）。

#### ⚠️ 降级判据（补充记录 §5(a) / §5(b)，**必须写进实现**）

上面只画了**顺序**，没定义「**什么时候算失败**」。不定义会导致一个隐蔽的正确性问题：

> **同一次 `scan` 混用两个源。**
> 最坏情况：扫 20 只，第 7 只时东财偶发失败 → 切 Yahoo → 第 8–20 只来自 Yahoo。
> 于是**前 6 只用东财的前复权基准、后 14 只用 Yahoo 的基准**，**两组数值不可直接比较**
> —— 这正是 PRD §4 与 T-4 一直在防的事（前复权基准日不同）。

**规定（三条）**：

| # | 规定 |
|---|---|
| ① | **首次数据请求失败 → 整体切换数据源**，**不是每只单独降级** |
| ② | **同一次工具调用内不换源** —— 一次 `scan` / `overview` 的结果必须**全部来自同一个源** |
| ③ | 输出必须标注**本次实际使用的源**（已有要求，这里补上"**整批同源**"的语义） |

**「失败」的判定**：网络层错误（超时 / 429 / `Empty reply` / DNS）。
**单只标的"无数据"（停牌、退市、代码错）不算降级信号** —— 那只是这一只没数据，标注该只即可。

**⚠️「早失败」是性能硬要求，不是优化**

若"每只票都等满超时才失败"：

```
20 只 × 10s 超时 = 200 秒  ≫  scan 的 timeoutMs = 45s
→ 超时会在扫到第 5 只时就触发，用户拿到一个残缺结果
```

**因此规定**：

> **首次数据请求用短超时（2–3 秒）快速探活**，失败即整体切源。
> **宁可"2 秒内换源成功"，不要"每只各等 10 秒然后整体超时"。**

对应参数：`FETCH_TIMEOUT_FIRST_MS = 3000`（首次探活）/ `FETCH_TIMEOUT_MS = 10000`（确定源之后的正常请求）。

**所有出网仍走 `ctx.safeFetch`**，域名白名单由 `skill.json` 的 `networkHosts` 声明后自动汇总进 registry。

## 6. 数据模型

### 6.1 `skill_kv`（新增，通用）

```sql
CREATE TABLE IF NOT EXISTS skill_kv (
  namespace  TEXT    NOT NULL,   -- 技能名，用于隔离
  key        TEXT    NOT NULL,
  value      TEXT    NOT NULL,   -- JSON 字符串
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (namespace, key)
);
```

> 技能**只能读写自己的 namespace**（由 `createSkillStore` 保证，不靠技能自觉）。
> ⚠️ **但命名空间隔离 ≠ 权限隔离** —— 还必须有 §3.1 的**运行时写闸门**，
> 否则声明 `read_only` 的技能也能写入自己的 namespace，污染别的技能会读取的数据。

### 6.2 自选股（`watchlist` 技能的数据）

存在 `skill_kv` 里，namespace = `watchlist`：

| key | value |
|---|---|
| `items` | `[{ "symbol": "600519.SH", "name": "贵州茅台", "market": "SH", "addedAt": 1789... }]` |
| `undo` | **可选**：最近 5 次操作前的数组快照（`[{at, snapshot}]`），用于"撤销上一步" |

**为什么整存一个数组而不是一行一支**：
自选股上限 20 支，整体读写的成本可以忽略；而一行一支会让"列表顺序"这种语义变复杂。
将来若要支持排序或备注检索，再迁移成独立表。

**关于 `undo`**：撤销栈是**可选优化，不是 L1.5 的前提**（评审决定 3 —— 条件②已由 `remove` 满足）。
若实现，采用 **"快照 + 整体回滚"**：每次 `add`/`remove` 前把当前数组压栈，撤销时整体覆盖回去。
这天然规避"加 A → 加 B → 删 A 后撤销哪一步"的索引漂移问题。**深度限制 5 次。**

> ⚠️ **`watchlist` 的符号解析必须优先本地**（评审 C-3）：
> 条件③修正为"不外发写入"后，只读联网查询在 L1.5 下是允许的；
> **但仍应优先用本地表解析**，解析不到时**返回候选让用户确认**，而不是静默联网。

## 7. 一次「茅台现在什么状态」的时序

```
用户：茅台现在什么状态
   │
   ├─ agent：组装 system（人格 + 技能清单）+ 历史 + 本轮 user（带时间前缀）
   ├─ provider 第 1 次请求 → 模型决定调用 market.overview({symbol:"茅台"})
   │
   ├─ runner.run("market", {...}, ctx)
   │     ├─ 闸门：存在 ✅ / 权限声明自洽 ✅ / risk=read_only 不确认 ✅ / 参数合法 ✅
   │     ├─ symbols.js：「茅台」→ 内置表命中 → 600519.SH（**零出网**）
   │     ├─ 缓存：6h TTL 未过 且 最后一根 K 线日期 == 最近已收盘交易日？→ 未命中
   │     ├─ safeFetch → 东财 push2his（1.600519, klt=101, fqt=1, lmt=500）  ★出网①
   │     │              └失败→ 降级 Yahoo chart（600519.SS）→ adjust.js 换算复权
   │     ├─ indicators.js：MA / RSI / MACD / 量比 / 区间位置 / 分位 / 波动率
   │     ├─ snapshot.js：渲染成 ≤800 单位（String.length）的状况说明书
   │     └─ 写缓存（内存 + ctx.store）
   │
   ├─ provider 第 2 次请求（带上 tool 结果）→ 模型把数字翻译成人话      ★出网②
   ├─ 流式回给界面，末尾附免责（**含"数据截至…"**）
   └─ 落库：user 原话 + 最终 assistant 文本（工具中间上下文不落库）
```

> ⚠️ **本时序图以 `overview`（单股查询）为例**，此时确实是"**只出网 2 次**"。
> **`scan` 不是 2 次** —— 它是 `N 只 × 1 次行情 + 2 次模型`（N ≤ 20）。见 PRD G6 的口径说明。

**关键点**：

- **数字全部来自工具**，模型只做翻译——这是 PRD §2.1 的落地方式。
- 一次工具调用拿到全部指标，而不是让模型调 7 次。
- **中断**：`scan` 每次循环前检查 `signal.aborted`，中断抛 `CANCELLED`（非 `TIMEOUT`）。

### 8.2 指标数值怎么验

**不能只验"跑得通"，要验"数字对"。** 做法：

1. 固定一段**已知的 K 线数据**（**从东财抄一份**，连同它算出的 MA/RSI/MACD 数值）
2. 作为 fixture 放进测试，并**标注数据抓取日期**
3. 断言我们的输出与东财**逐项一致**

**基准与容差（评审 T-4）**：

| 项 | 规定 |
|---|---|
| **基准软件** | **东财** —— PM 的看盘软件就是东财，**与主数据源同源**，因此不存在"两源前复权基准日不同"的偏差 |
| **浮点容差** | **相对误差 ≤ 1e-6** |
| **fixture 时效** | 每个 fixture 标注抓取日期；**跨天不可复现是正常的**（前复权基准移动，MK13 已改为"同一天内可复现"）|

**已在 `indicators.test.js` 中落地的部分**：因当前**没有可核对的真实 fixture**，
该测试**只断言数学恒等式与口径**（MACD 柱 = 2×差值、EMA 用 SMA 做种子、RSI 用独立复算比对、
样本不足返回 null），**刻意不硬编码任何"真实行情软件的精确数值"**——
**伪造精确期望值等于给自己放假**。真实对账待有数据后按上表补齐。

这是唯一能防止"复权算错 / MACD 柱口径不对 / EMA 种子用错"的手段——**这三种错误在代码上看都"很正常"**。

## 10. 风险与备选

| 风险 | 触发信号 | 备选 |
|---|---|---|
| **东财接口变更 / 端点级封锁** | 主源连续失败 | 降级 Yahoo；若两者都不可用 → **如实告知"数据源暂时拒绝，过会儿再试"**（**不要说"查不到这只股票"**）|
| **东财在国内不可用**【待验证】 | M-0 国内实测返回 `000` | **回到 Yahoo 单源 + 讨论代理**，需重新评审数据源方案 |
| **Yahoo 国内不可达**【推断】 | 备源一直失败 | 属预期内；国内本就是"东财单主源"，**必须诚实告知用户没有第二源** |
| **限流被封（双向）** | 429 / `Empty reply` | 缓存 + 串行 ≥500ms + **绝不激进重试**（退避）。实测：东财 ~160 次/10 分钟即硬封、Yahoo ~40 次/2 分钟触发 429 |
| **中文名检索不准** | "茅台"解析失败 | **已有实测结论**：Yahoo 搜索不可用 → 内置表做大（约 320 条）+ 东财搜索为主力 |
| **复权口径与行情软件不一致** | MK3 / MK4 对照不一致 | **基准 = 东财**，且主源就是东财 → 同源无偏差；仅备源 Yahoo 路径需注意基准日差异 |
| **MACD 柱口径争议** | 与某软件对不上 | 已在 §5.3 冻结为 `2×(DIF−DEA)`；若东财不是这个口径，改 `PARAMS` 一处常量即可 |
| **`scan` 首次 7–19 秒太慢** | 用户抱怨 | 提高并发（风险是更容易被限流）；或先返回缓存、后台补拉。**PM 已决定"先做着看效果"** |
| **L1.5 被滥用** | 不该自动执行的技能标成 L1.5 | 判定条件已在 §3.2 写死为三条硬约束 + **§3.1 运行时写闸门兜底**；新增 L1.5 技能必须在 PRD 里论证 |
| **用户误信解读** | —— | 三层边界 + 禁止清单 + 语料回归（MK12）+ **数字溯源测试** |
| **图表上线后内存超限** | A9 破 500MB | 图表窗口默认隐藏、按需创建；或"用完即销毁"（与"窗口只创建一次"的纪律冲突，需单独论证） |
