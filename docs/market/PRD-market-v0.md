## 0. 这份文档为什么是"功能 PRD"

现有三份 PRD 是**按层**切的（Body / Brain / Skill）。而行情这个需求是**横切**的：

| 关注点 | 落在哪一层 |
|---|---|
| 取数、复权、指标计算、自选股存储 | Skill |
| 解读约束、禁止输出、免责 | Brain（提示词与闸门） |
| 自选股列表 / 将来的图表 | Body |

按层拆开会散架（同一件事被切成三段，改一处要翻三份文档）。所以这里**单独成篇**：

- 本文档承载**功能级的完整需求**；
- 三份层 PRD 只加一句引用（见 §11「对现有文档的影响」）；
- 技术落点在 `SDD-market-v0.md`。

## 1. 背景与目标

### 1.1 一句话

用户问「茅台现在什么状态」，NONO 能给出**基于真实日线数据、本地计算指标**的解读——
而不是一段听起来很专业的废话。

### 1.2 它解决什么问题

打开任何行情软件，你看到的都是一堆数字：价格、涨跌幅、五条均线、MACD、RSI、成交量……

**缺的从来不是数字，是翻译。**

知道"RSI 是 28"没有意义；知道"RSI 28，处于近一年最低的 12% 分位"才有意义。
知道"MACD 死叉"没有意义；知道"这是三个月来第一次死叉，同时成交量是 20 日均量的 1.8 倍"才有意义。

这个功能做的就是**把数字翻译成状态**。

### 1.3 v0 目标

| 编号 | 目标 | 可衡量标准 |
|---|---|---|
| G1 | **覆盖 A 股** | 沪深两市可查，支持中文名与 6 位代码两种输入（美股/港股移交 v1+，见 §1.4） |
| G2 | 数据可信 | **前复权**日线；指标数值与东财（PM 看盘软件）逐项核对一致 |
| G3 | 有自选股 | 最多 20 支，可增删查，重启后仍在 |
| G4 | 能解读 | 给出「状况说明书」，带**客观分位**，不产生买卖信号 |
| G5 | 不惹麻烦 | 不封 IP、不因为一个数据源挂掉就整个功能失效 |
| G6 | 成本可控 | 单股查询（`overview`/`quote`）≤ **1 次行情出网**；`scan` ≤ **20 次行情出网**（＝自选股上限），**另加 2 次模型调用** |

> **G6 口径说明（评审 B-1 修订）**：原稿只写"扫描 ≤ 20 次出网"，与 `SDD-market` §7 的"只出网 2 次"矛盾。
> 实际情况：`scan` = N 只 × 1 次行情（N ≤ 20）**＋ 2 次模型调用**（一次决策、一次叙述）。
> `SDD-market` §7 的"2 次"描述的是**单股 `overview`** 的情形，不是 `scan`。

### 1.4 非目标（v0 明确不做）

| 不做 | 原因 |
|---|---|
| **图表**（K 线 / 均线 / MACD 可视化） | 占一半以上工作量但不是价值核心；**计划在后续版本做**，见 §9 |
| **美股 / 港股** | **v0 只做 A 股**（评审决定 6）。三市场要额外处理 3 个交易所前缀、夏令时、港股零填充、三套时区与节假日——**工作量约等于 A 股本身**。移交 v1+ |
| **盘中实时报价** | 只做日线就够（见 §3.1），而且能完全规避封 IP 风险 |
| 分钟级 / 分时 / 周期切换 | 同上 |
| **买卖信号、择时提示、点位预测** | 见 §2，这是本功能的**红线** |
| 回测、选股器、条件预警 | 那是量化工具，不是桌宠技能；单独立项 |
| 下单 / 交易 | **永久红线**（PRD-Skill §2.3） |
| 财报 / 基本面深度分析 | v0 只做技术面 + 价格位置 |
| 全市场扫描 / 涨跌幅榜 | 成本与限流都不可控 |

## 2. 能力边界（本 PRD 最重要的一节）

### 2.1 三层输出模型

用户想要的"建议"其实混了三种东西。本功能**只做前两层，并明确划出第三层**：

| 层 | 谁负责 | 内容 | 可验证性 |
|---|---|---|---|
| **① 事实层** | 本地确定性计算 | 价格、涨跌幅、均线位置、RSI / MACD 数值、成交量对比、**历史分位**、波动率 | ✅ 可复现、可核对 |
| **② 解读层** | LLM 只做翻译 | "最近跌得比较急"、"波动比平时大"、"这是三个月来第一次死叉"、"超卖不等于会反弹" | 🟡 措辞可回归测试，数字必须来自① |
| **③ 判断层** | **不做** | "该不该买"、"会不会涨"、"现在是不是底部" | ❌ 不可验证 = 不该做 |

**一句话原则：系统负责把状态讲清楚，模型负责翻译成人话，谁都不负责预测。**

### 2.2 「高位低位」= 分位数，而不是"高不高"

这是本功能能诚实满足用户需求的关键设计。

用户问"现在是不是高位"，**可以客观回答**：

> 当前价 1680，处于近 250 个交易日的 **87% 区间位置**（区间 1420–1725），
> 且高于 20 / 60 / 250 日均线。

这是**事实**，可计算、可验证、可回溯。

而"高位了该不该卖"是**判断**，不做。

**所以：凡是能用"分位数 / 相对位置 / 与均线的关系"表达的，都归入事实层。**
这覆盖了用户绝大部分"高位低位"的真实需求，而且比一个模糊的"偏高"有用得多。

### 2.3 明确禁止的输出

以下内容在 **prompt 层硬性禁止**，并纳入回归语料：

| 禁止 | 例子 |
|---|---|
| 买卖指令 | "建议买入"、"可以考虑入手"、"该止损了" |
| 点位预测 | "会涨到 1800"、"支撑位在 1500" |
| 时间预测 | "下周会反弹"、"短期内看好" |
| 确定性断言 | "已经见底"、"趋势反转了" |
| 目标价 / 评级 | "目标价 2000"、"强烈推荐" |
| 对未提供数据的臆测 | 编造财报数据、编造新闻、编造主力资金流向 |

**允许**的表达：

> "RSI 28，属于近一年偏低区间（12% 分位）。历史上这个区间之后有涨有跌，不构成任何提示。"
> "价格刚跌破 60 日均线，这是三个月来第一次。"
> "波动率处于近一年高位，意味着最近波动比平时大。"

### 2.4 为什么不做"硬结论"

不是因为合规（自用玩具），而是因为**它不准，而且不准得很隐蔽**：

1. **MA / RSI / MACD 全是滞后指标**。它们描述"已经发生了什么"，不预测"将要发生什么"。
2. **LLM 在这个场景下极易滑向"给出一个听起来合理的结论"**。它会把噪声包装成专业感。
3. **一段错误的买卖建议，比没有建议更糟**——如果用户信了，这个工具就是负价值的。

> **宁可给一份诚实的状态报告，也不给一个漂亮的错误答案。**

### 2.5 免责声明

- **触发条件（评审 C-5 统一）**：**只有当回复中包含"事实层数字"时才附**免责声明。
  - ✅ 附：回复里出现了价格、涨跌幅、RSI、MACD、分位、量比等任何事实层数值
  - ❌ 不附：纯交互回复（"已加入自选""帮你删掉了"）与纯闲聊
  - 理由：给"帮我加个自选"也附免责，既啰嗦又会让免责本身失去分量。
- **免责必须同时包含数据时效**（评分 P-2）：只说"不构成投资建议"不够，
  还必须说清"**数据截至 X 日收盘**"——因为 v0 只做日线，且盘中问价只能给上一交易日收盘价。
- 措辞由实现拟定，需保留"**不构成投资建议**"与"**数据截至…**"两层意思。
- 首次使用时在设置页或气泡里**说明一次**本功能的能力边界（说什么、不说什么）。

## 3. 数据层需求

### 3.1 只做日线（v0 的关键降级）

**这是整个需求里最重要的一个范围决定。**

| | 日线 | 盘中实时 |
|---|---|---|
| 拉取难度 | 🟢 低 | 🟡 高 |
| 封 IP 风险 | 🟢 基本没有（一天一次） | 🔴 有（轮询会被盯上） |
| 复权支持 | 🟢 好 | 🔴 差 |
| 对指标的价值 | **全部指标都基于日线收盘价** | 边际提升很小 |

**结论：v0 只拉日线。** 这样"会不会被封 IP"这个问题**根本不会出现**——
20 支股票 × 每天刷新 1 次 = 20 个请求/天，任何数据源都不会在意这个量级。

代价：盘中问"现在多少钱"，只能给**上一交易日收盘价**。这必须在输出里**明确标注**（见 §3.5）。

### 3.2 必须前复权（硬约束）

**这是最容易错、错了最致命的一条。**

股票除权除息那天价格会跳空，如果不复权：

- 均线会被砸出一个**假的下穿**
- MACD 会出现**假死叉**
- 用户看到的"技术形态"**全是假的**

所以：

| 要求 | 说明 |
|---|---|
| 一律使用**前复权**（最新价不变，历史价调整） | 技术分析看的就是前复权 |
| 复权必须作用在 **O / H / L / C 全部四个价格**上 | 只调收盘价会让 K 线形态失真（虽然 v0 不出图，指标仍基于收盘，但保持一致更安全） |
| 数据源必须能提供复权，或用原始价 + 复权因子自行换算 | **双源两种做法**（见 `SDD-market-v0.md` §5.1）：<br>• **东财（主源）**：`fqt=1` **直接返回前复权 OHLC**，不需要自己换算<br>• **Yahoo（备源）**：返回原始 OHLC + `adjclose`，**必须自行换算因子** |
| **验收必须有除权案例** | 拿一支近期除权的票，验证复权前后均线连续、无跳空（MK3） |

### 3.3 市场范围与符号

**v0 只做 A 股**（决定：美股/港股移交 v1+）。

| 市场 | 例子 | 输入应支持 |
|---|---|---|
| A 股 | 贵州茅台 / 600519 / sh600519 | 中文名、6 位代码 |

- 内部统一符号格式 `<code>.<MARKET>`，如 `600519.SH` / `000001.SZ`；各数据源转换见 `SDD-market` §5.2。
- **必须支持中文名输入**——不该要求用户背代码。
- 名字解析失败时：**明确报错并给出候选**，不许猜（复用天气技能 WX-4 的原则）。
- **符号解析顺序**：本地表 → 东财搜索 → Yahoo search 兜底（见 SDD §5.2）。
  ⚠️ **已知事实**：**Yahoo 搜索不支持中文股票名**（实测「茅台」「宁德时代」「长江电力」均无结果），
  所以中文名解析**必须依赖本地表 + 东财搜索**，Yahoo 只在英文/代码直通时有用。

### 3.4 缓存与限流

**缓存规则（评审 B-5 合并为一条）**

> **命中 = ① 距上次拉取 < 6 小时，且 ② 缓存里最后一根 K 线的日期 == 该标的最近一个已收盘交易日。**
> 两条同时成立才算命中，否则重新拉取。

原稿的"日线缓存 / 报价缓存 5 分钟"两条是对**两种数据形态**的描述，但 **v0 只做日线、不存在"报价"**，
所以统一按上面一条执行。`quote` action 的数据也从**日线最后一根**派生，**不额外请求**（见 SDD §5.4）。

- **不判断节假日**：靠"最后一根 K 线日期 + TTL"两条自然规避——长假里不会反复拉取。
- **盘后宽限期（评审 D-1）**：A 股 15:00 收市，但当日 K 线通常 **15:30–16:00** 才稳定。
  因此收盘后 **60 分钟内不认为"当日数据可用"**，此时按上一交易日的数据回答。

| 要求 | 说明 |
|---|---|
| 串行 + 节流 | 批量扫描时**串行**请求，请求间隔 **≥ 500ms**（评审 A-2：东财按源 IP 限流，200ms 偏激进） |
| 单次上限 | 一次扫描不超过自选股上限（20） |
| 失败不放大 | 某只票拉失败**不能**导致整次扫描失败；单只失败单只标注 |
| **缓存是保护，不是优化** | 重复查询**绝不**重复出网。开发期反复调试会撞限流（实测：东财 ~160 次/10 分钟即硬封） |

### 3.5 数据时间戳（硬约束）

**任何输出都必须带数据时间。**

- 格式：`数据截至 2026-09-11 收盘`
- 理由：日线数据有"今天有没有"的问题，加上**盘后数据延迟**（见 §3.4 宽限期），
  不标时间会导致用户把隔夜数据当最新。
- 措辞必须与其他约束一致：**免责声明里也必须带这句**（见 §2.5）。

## 4. 指标定义（参数写死）

> ⚠️ **参数必须写死并写进文档。** 含糊的参数（"常用的 MACD"）会让同一个问题在不同时间得到不同答案，
> 也让"解读"无法复现。以下为 v0 冻结定义。

| 指标 | 参数 | 公式要点 | 建议样本 |
|---|---|---|---|
| **MA** | 5 / 10 / 20 / 60 / 250 | 简单移动平均，收盘价 | 250 |
| **RSI** | 14 | **Wilder 平滑**：种子为前 14 期简单平均，之后 `avg = (prev×13 + cur) / 14`；`RSI = 100 − 100/(1+RS)`；`avgLoss = 0` 时 RSI = 100 | 60 |
| **MACD** | 12 / 26 / 9 | `DIF = EMA12 − EMA26`；`DEA = EMA9(DIF)`；**柱 = 2 × (DIF − DEA)**（A 股软件惯例，**必须乘 2**，否则和行情软件对不上）；EMA 种子用**前 n 期简单平均** | 60 |
| **量比** | 20 日 | 当日成交量 ÷ 近 20 日均量（**不含当日**） | 60 |
| **区间位置** | 250 日 | `(P − min250) / (max250 − min250) × 100%` | 250 |
| **分位**（读法见下） | 250 日 | `count(收盘 ≤ 当前价) / 250 × 100%` | 250 |
| **波动率** | 20 日年化 | 日收益率标准差 × √252 | 60 |
| **均线关系** | — | 价格与各均线的上下关系；以及**最近一次上穿/下穿发生在几天前** | 250 |

- **量比口径已统一为"不含当日"**（评审 B-4）：原 PRD 写"当日 ÷ 近 20 日均量"（含当日），
  SDD 写"不含当日"，两者差一天会导致数值差几个百分点，MK4 对账会立刻暴露。
  现统一为 **`今日成交量 ÷ 前 20 日均量`**。

> ⚠️ **「分位」的读法极易搞反（评审 B-2）**
>
> `count(收盘 ≤ 当前价) / 250` 表达的是「**近 250 个交易日里，有多少比例的日子收盘价低于当前价**」。
>
> - 返回 **12%** ⇒ 只有 12% 的日子比现在低 ⇒ 当前价**偏低**
> - 返回 **87%** ⇒ 87% 的日子比现在低 ⇒ 当前价**偏高**
>
> 多数人的直觉是"12% 分位 = 排在后 12%"，恰好一致；但**只给百分数仍然容易被误读**。
>
> **因此硬性要求**：模型输出时**不允许只给百分数**，必须附中文说明，例如
> "近一年只有 12% 的交易日收盘价低于当前价"。MK13 的验收也据此检查。

> ⚠️ **「建议样本」与「能算出来的下限」是两件事**（v0.2 修订）
>
> 本列给的是**建议样本**：低于它，数值**仍会给出，但会被显式标注"样本偏短、相对不可靠"**。
> 而**数学上能算出来**的下限要低得多（代码里的 `MIN_SAMPLES`）：
>
> | 指标 | 能算出来（`MIN_SAMPLES`） | 建议样本（可靠） |
> |---|---|---|
> | RSI | 15（14 期涨跌幅 + 1） | **60** |
> | MACD | **34**（26 暖机 + 9 DEA） | **60** |
> | 量比 | 21（20 日均量 + 当日） | **60** |
> | 波动率 | 21（20 个收益率 + 1） | **60** |
> | 区间位置 / 分位 | 250 | 250 |
>
> **修这条的原因**：原稿把「最小样本」只写了一个数，于是文档说"MACD 不足 60 根要标注不可靠"，
> 而代码在 34 根就**静默**给出 MACD —— **两边不一致，且静默的那一侧更危险**。
> 现在两档分开：**算不出来就不给**，**算得出来但偏短就标注**。

**为什么同时给"区间位置"和"分位"**：前者直观（"在最高最低之间哪个位置"），
后者统计意义更强（"历史上多少天比现在低"）。两个都便宜，都给。

**数据量要求**：默认拉取 **2 年**日线（约 500 根），用最后 250 根算分位，全部用于 MACD 预热。
不足 250 根时（新股）**必须明说样本不足**，不许用短样本装成完整结论。

## 5. 自选股

| 项 | 要求 |
|---|---|
| 容量 | **最多 20 支** |
| 字段 | 符号、名称、市场、加入时间、备注（可选） |
| 操作 | 添加、删除、列出 |
| 持久化 | **本地 SQLite，重启后仍在** |
| 去重 | 同一支重复添加视为幂等，不报错 |
| 容错 | 添加时若符号解析不出来，**拒绝并给候选**，不许存进去 |

### 5.1 风险等级：新增 `local_reversible`（L1.5）【已采纳】

按现有多级模型（`PRD-Skill-v0.md` §4.2）：

- `read_only` → L1 自动
- `local_write` / `external_send` → L2 **需用户确认**
- `irreversible` → L3 禁止

**问题**：把"加一支自选股"标成 `local_write`，就意味着**每加一支都要弹确认框**。

这很糟，而且**反而降低安全性**：

> 一个每次都弹、每次都无害的确认框，会训练用户闭着眼睛点"允许"。
> 等真正危险的操作（比如发邮件）出现时，用户已经不会看了。

这违反"**不允许盲确认**"原则的**本意**（原意是防止用户在不理解的情况下放行）。

**已新增一档（评审决定 3，PM 已确认）：**

| 等级 | 判定 | 行为 |
|---|---|---|
| **L1 自动** | 只读、纯本地 | 直接执行 |
| **L1.5 `local_reversible`** | **只写本技能的 `ctx.store` + 存在反向操作 + 不外发写入** | **直接执行（不弹框）**，但**结果必须在气泡里可见**（"已加入自选：贵州茅台"） |
| **L2 需确认** | 外发数据、读隐私内容、不可撤销的本地写 | 弹确认框 |
| **L3 禁止** | 涉及金钱或不可逆后果 | 硬拒绝 |

#### 判定条件（写死，防止将来滥用）

> **同时满足三条才算 L1.5**：
> ① 写入范围**仅限本技能的 `ctx.store`**；
> ② 存在**一条反向操作**能完整撤销（如 `add` ↔ `remove`）；
> ③ **不产生任何外发写入** —— 即不通过网络发送用户数据。
> （出网**只读**查询不受此限；原稿措辞"不产生任何出网请求"比 L1 还严，已按评审决定 10 修正。）
>
> **任一条不满足即降为 L2。**

#### 「不弹框」之后的安全网

因为**不弹确认框**，用户失去了"事前拦截"，只剩"事后纠正"。因此：

- **结果必须在气泡里可见** —— **必做**
- **自选名单每行可删** —— **必做**（见 §8）
- **"撤销上一步"按钮** —— ⚠️ **可选优化，不是 L1.5 的前提**
  （条件②已由 `remove` 满足；若要做，用"快照 + 整体回滚"）

**配套改动**（见 §11）：`PRD-Skill-v0.md` §3.2/§4.2、`schema.js` 的 `RISK_TO_LEVEL`、
以及 **`ctx.store` 的运行时写闸门**（`read_only` 技能不得写入）。

**⚠️ 注意**：`ctx.store` **目前尚不存在**（`runner.js` 只注入 `safeFetch`），
因此写闸门是**实现时不可遗漏的要求**，不是已存在的保护。

## 6. 技能接口（给模型看的）

### 6.1 为什么不放一个技能里

**`risk` 是 per-skill 的，不是 per-action 的。**

如果把"查行情"（只读）和"加自选"（写）塞进同一个技能，整个技能就得标成写操作，
结果是**每次查行情都要弹确认框**——这显然不可接受。

所以拆成两个：

| 技能 | 职责 | 风险 |
|---|---|---|
| **`market`** | 查行情、算指标、批量扫描 | `read_only`（L1） |
| **`watchlist`** | 自选股增删查 | `local_reversible`（L1.5，见 §5.1） |

### 6.2 `market`

| action | 用途 | 输出 |
|---|---|---|
| `quote` | 轻量报价：最新价、涨跌幅、成交量、数据时间 | 3–5 行 |
| `overview` | **完整状况说明书**（推荐）：价格 + 均线位置 + RSI + MACD + 分位 + 波动率 + 量能 | 10–15 行 |
| `scan` | **批量扫描全部自选股**，输出紧凑表格 | 每只一行 |

- 入参：`symbol`（名字或代码）。
- ⚠️ **`scan` 忽略 `symbol`**（评审 P-3）：它扫的是**全部自选**，不需要 symbol。
  参数 Schema 里 `symbol` 为可选，`scan` 时不读它——否则模型的参数校验会打架。
- **`scan` 是最重要的设计**：一次工具调用拿到 20 只的状态，
  而不是让模型循环调 20 次 `overview`（那样要 20 次工具往返，又慢又贵）。

### 6.3 `watchlist`

| action | 用途 |
|---|---|
| `add` | 加一支（解析名字 → 存） |
| `remove` | 删一支 |
| `list` | 列出全部自选 |

### 6.4 批量扫描的 summary 预算

`summary` 有 **800 单位上限**（`runner.js` 的 `SUMMARY_LIMIT`），但 20 只股票的完整指标远超这个数。

> **单位定义（评审 C-3）**：`SUMMARY_LIMIT = 800` 的判定基准是 **`String.length`（UTF-16 码元）**，
> **不是字节数**。中文 UTF-8 一字 3 字节，若按字节算会超标 3 倍。**实现与测试都必须按 `String.length` 核对。**

**这是必须提前设计好的约束**，方案：

1. `scan` 使用**紧凑表格格式**，每只一行，例如：
   ```
   名称      现价    涨跌   RSI  年位置  量比
   贵州茅台  1680.0  +1.2%  28   87%     1.8
   ```
   20 行 × 约 38 单位 ≈ **760 单位**，刚好放下。
2. 超限时的**降级策略 —— 减行，不减列**（评审 D-4）：
   - **列必须固定**。原稿"先丢量比列、再丢区间位置列"会让列数变化，
     模型可能把第 5 列当成第 4 列读错。
   - 改为：**按"涨跌幅绝对值从大到小"保留前 N 只**（信息量最大的优先），
     末尾加上一行 `（另有 M 只未显示，可用 overview 单查）`。
3. **不允许**默默截断成半行，也**不允许默默丢列**——截断与省略都必须显式说明。
4. 表格若仍超限，继续减少行数直到满足；**绝不切断某一行**。

## 10. 验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| MK1 | **A 股可用** | 沪深各取一支（如茅台 600519、平安银行 000001），都能查到 |
| MK2 | 中文名输入 | 输入"茅台"能解析到 600519；解析不了时给候选而不是猜 |
| MK3 | **复权正确** | 取一支**近期除权**的票，复权后的均线连续、无跳空；与东财对照一致 |
| MK4 | 指标正确（**限东财路径**） | MA / RSI / MACD / 分位 的数值与**东财**逐项核对一致（相对误差 ≤ 1e-6） |
| MK5 | **MACD 柱口径**（**限东财路径**） | 与 A 股行情软件一致（柱 = 2×(DIF−DEA)） |
| MK6 | 数据时间戳 | 每次输出都带"截至哪天收盘"；**含盘后宽限期的正确表述**（如 15:10 问，应给上一交易日） |
| MK7 | 自选股持久化 | 加 20 支，重启应用后仍在 |
| MK8 | 自选股上限 | 第 21 支被拒绝并说明 |
| MK9 | 缓存生效 | 同一交易日重复查询不产生第二次出网 |
| MK10 | 限流 | 扫描 20 只时**串行且间隔 ≥500ms**（可用日志核对） |
| MK11 | 单只失败不拖累 | 人为让某一只失败，其余 19 只正常返回 |
| MK12 | **不产生买卖建议** | 固定语料（20 条）回归：**自动关键词黑名单 + 人工打分**双轨，输出中不出现 §2.3 任何禁止表述 |
| MK13 | 分位可复现 | **同一数据、同一天内**，分位数与手工计算一致（跨天因前复权基准移动而不同，属正常） |
| MK14 | 免责声明 | 回复**含事实层数字时**都带免责，且免责含"数据截至…" |
| MK15 | summary 预算 | 20 只的 `scan` 结果 `String.length ≤ 800`，**且未被无声截断或无声丢列** |
| MK16 | 样本不足 | 对上市不足 250 个交易日的新股，明确说明样本不足 |
| MK17 | 出网白名单 | 只有声明的行情域名可访问；飞行模式下全部拒绝 |
| **MK18** | **自选名单零出网**（新增） | 打开自选名单视图**不产生任何网络请求**；数据源全部不可用时仍能看到名单 |
| **MK19** | **中断与超时可区分**（新增） | `scan` 执行中点「停止」→ 立即中断且报 `CANCELLED`（**不是 `TIMEOUT`**） |
| **MK20** | **备源路径的数值口径**（新增） | 走 Yahoo 备源时：① 输出**必须标注数据源**；② 前复权基准与东财**不同属正常**，因此 **MK4/MK5 不适用于备源路径**；③ 备源数值与 **Yahoo 官方图表**一致即可。<br>**理由**：两源前复权基准日不同 → 备源路径下 MK4/MK5 **必然不成立**，不能拿东财的数值去要求它 |
| **MK21** | **同一次调用不混源**（新增） | 一次 `scan` / `overview` 的结果**全部来自同一个源**（不得出现前几只东财、后几只 Yahoo）；降级是**整体切换**，不是逐票切换 |

## 12. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **数据源变更 / 失效** | 功能整个不可用 | **东财主源 + Yahoo 备源**；失败**如实报错**。<br>⚠️ **必须诚实**：PM 在国内使用，而 **Yahoo 在国内大概率不可达**，所以**国内实际是单主源**——东财挂掉就等于当天查不到行情，**不许装作有备份** |
| **限流被封** | 功能间歇性失效 | 只做日线（20 次/天，余量充足）+ 缓存 + 串行节流 ≥500ms + **绝不激进重试**。<br>**实测教训**：开发期 ~160 次/10 分钟即触发东财**路径级封禁**、Yahoo 触发 429。见 §12.1 |
| **`scan` 把自己打封**（缓存 bug 时） | 用户当天彻底查不到行情，且会以为软件坏了 | 正常 20 次/天有 8 倍余量；但**一个缓存 bug 就可能在同分钟内打出上百次**。→ **§12.1 第 5 条「出网次数自检」是唯一早期信号** |
| **被封时的措辞误导** | 用户以为"这只股票不存在" | 说"**数据源暂时拒绝了请求，过会儿再试**"，**不要**说"查不到这只股票" |
| **复权算错** | 指标全错，用户基于假信号判断 | MK3 专项验收；**东财路径直接用 `fqt=1`；Yahoo 路径的因子换算算法写进 SDD 并单测** |
| **同一次 scan 混源** | 前几只东财、后几只 Yahoo，**两组数值不可直接比较** | MK21 + SDD §5.6「降级判据」：**首次失败即整体切换**，同一次调用内不换源 |
| **备源路径下 MK4/MK5 必然失败** | 拿东财的数值要求 Yahoo 路径，永远验收不过 | MK20：MK4/MK5 **限定东财路径**；备源路径改为"与 Yahoo 官方图表一致 + 标注数据源" |
| **模型编造数字** | 最严重——用户可能据此操作 | 数字**只能**来自技能；prompt 硬性禁止；MK12 回归 + **数字溯源测试** |
| **短样本装成完整结论** | 新股给出误导性分位 | MK16：不足 250 根必须明说 |
| **L1.5 被滥用** | 将来有技能把危险操作标成 L1.5 | 判定条件写死为"只写本技能 `ctx.store` + 存在反向操作 + 不外发写入"，越界即 L2；**并需 `ctx.store` 运行时闸门兜底** |
| **用户误信解读** | 亏损与信任损失 | 三层边界 + 免责 + 禁止清单；UI 上说明能力边界 |
| **summary 超限** | 扫描结果被无声截断，模型看到残缺数据 | MK15 + 显式降级策略（**减行不减列**，§6.4） |
| **开发期反复打真实接口** | 撞限流、被封 IP | **一律用 fixture**，不打真实接口（MK10 用日志核对） |

### 12.1 限流纪律（**五条，属核心安全属性**）

> ⚠️ **为什么是"核心安全属性"而不是"注意事项"**：
> 补充记录实测发现，东财的封禁是**路径级反爬**（同一主机不存在的路径返回 404、搜索端点 200 正常，
> 只有**行情 API 路径**被拒），且**封禁触发条件是"请求模式"而不是"地理位置"**。
> 本机在 11:40–11:46 还是可用的（最快 137ms），累计约 **160 次**请求后即持续 `HTTP 000`，25 分钟未恢复。
>
> **推论**：**国内同样会被这种封禁触发**。正常使用 20 次/天有 8 倍余量，
> 但**一个缓存 bug 就可能在同分钟内打出上百次请求** → 用户当天彻底查不到行情，还会以为软件坏了。

| # | 纪律 |
|---|---|
| 1 | **缓存是保护，不是优化** —— 重复查询**绝不**重复出网 |
| 2 | **绝不激进重试** —— 被 429 / 断连后必须**退避**，否则加深封禁 |
| 3 | **被封时的措辞要诚实** —— "数据源暂时拒绝了请求，过会儿再试"，**不是**"查不到这只股票" |
| 4 | **开发调试一律用 fixture** —— 不打真实接口（实测已证明会封 IP） |
| 5 | **🆕 出网次数自检** —— 单次 `scan` 的实际请求数**超过预期（如 > 25）时记 `warn` 日志**。<br>**因为那意味着缓存没生效——这是发现缓存 bug 的唯一早期信号。** |
