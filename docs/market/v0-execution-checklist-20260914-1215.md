## A. 前置验证（M-0）

| # | 动作 | 说明 |
|---|---|---|
| A-1 | **在国内网络下验证东财 K 线端点** | **唯一可能推翻数据源方案的变量**，1 分钟 |

**🆕 修正后的验证命令**（终版原命令有两个坑，见 addendum §2）：

```bash
curl -s -m 12 \
  "https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600519&fields1=f1,f2,f3&fields2=f51,f53&klt=101&fqt=1&lmt=3" \
  | head -c 300
```

| | 判据 |
|---|---|
| ✅ 通过 | 输出里能看到 `"klines":["2026-...` |
| ❌ 不通 | 空输出，或 `curl: (52) Empty reply from server` |
| ⚠️ 其它 | 把完整输出贴出来再判断 |

**🆕 与终版的两处差异**：
1. `fields1=f1` → **`fields1=f1,f2,f3`**。本机所有**已知成功**的请求用的都是三字段组合；单字段组合**未经证实可用**，若它本身不合法，国内也会报错 → **会把整个数据源方案错误推翻**。
2. 去掉 `-o /dev/null`。终版只校验状态码，**`HTTP 200 但 data 为空`会被误判为通过**。

**🆕 执行时机调整**：M-0 从「**M-1 的前置**」改为「**与 M-1 并行**」。理由见 §F。
